# 卡图尺寸规范（2026-09-11）

适用于所有 **卡面美术**（`.gtnmod` 包内 `card-art/`、`assets/cards/`、
`assets/card-art/`、`cards/` 下的 `.svg`）。
`status-icons/`、`ui-icons/`、`assets/icons/` 等小图标**不适用**本规范，各有各的画布。

## 一、规范

1. **画布**：根元素写 `viewBox="0 0 283.46 283.46"`，**不要**写 `width` / `height`
   （写了会把图钉到固定像素尺寸，卡面缩放会失真）。
2. **画布必须是 1:1 正方形**——这是硬性要求：`object-fit: contain` 会把画布塞进方形卡面框，
   非正方形画布会让图形的实际显示大小/比例跟别人不一致。
3. **内容占比**：图形内容（可见像素包围盒）最长边 = 画布的 **60% 左右**（参考区间 0.55–0.65）。
   这一条是"参考"而不是"必须"：**画布已经是 1:1 的图，内容留白多少属于美术的自由**，
   不要为了凑数字去缩放它们。
4. 只有**画布不正确**（非 1:1）的图才做规整，且规整时按"最小改动"把可见尺寸落进 0.55–0.65，
   不做大幅缩放。

## 二、为什么要这样

卡面渲染容器是固定盒子 + contain 缩放（`static/css/style.css`）：

```css
.card-art { width: 88%; height: var(--card-art-height); display: flex; align-items: center; justify-content: center; }
.card-art img { width: 98%; height: 98%; object-fit: contain; }
```

画布按 `contain` 缩放进这个盒子，所以**"内容在画布里的占比"直接等于视觉大小**。
画布尺寸统一但内容占比不统一，看起来就是"有的牌图大、有的牌图小"。

历史遗留的三类问题：

| 类别 | 现象 | 处理 |
| --- | --- | --- |
| **非 1:1 画布**（画布本身错误） | 贴边导出或横竖比例不对，显示尺寸/比例与别人不一致 | **已修**：`garden:candle`、`jungle:dianthus`、`jungle:maple`、`sewers:cheese` |
| 1:1 画布但尺寸非 283.46 | 例如 100×100；`contain` 下视觉等价，只是写法不同 | 不动（画布正确） |
| 1:1 画布、内容占比与 0.60 有出入 | 例如 0.44 或 0.82，属于美术留白差异 | 不动（画布正确） |

## 三、工具

`tools/normalize_card_art.py`：渲染测量内容包围盒 → 包一层
`<g transform="translate(...) scale(...)">` → 重写画布。

```bash
cd Python联机版

python tools/normalize_card_art.py --all                 # 只报告（默认不改文件）
python tools/normalize_card_art.py --all --canvas-only            # 只报告"画布错误"的图
python tools/normalize_card_art.py --all --canvas-only --apply    # ★ 推荐：只修画布错误的图
python tools/normalize_card_art.py --all --canvas-only --verify   # 校验画布是否都 1:1
# 全量归一（连内容占比也拉到 0.60）——会改很多美术，默认不要用
python tools/normalize_card_art.py --all --apply

# 想换目标也可调参（默认就是规范值）
python tools/normalize_card_art.py --all --apply --size 283.46 --ratio 0.60 --band 0.05
```

依赖：`cairosvg` + `Pillow`（只在测量时用；没有会报错并提示安装）。

## 五、验收口径

1. `python tools/normalize_card_art.py --all --canvas-only --verify` 输出"全部符合规范"（画布都 1:1）；
2. 抽查渲染：任意图在 192×192 下渲染，alpha 包围盒最大边 / 192 ∈ [0.55, 0.65]，
   且左右留白差、上下留白差 < 2%；
3. 编辑器里导入对应包，卡面预览的图大小一致（编辑器不需要改动，卡面由游戏渲染器绘制）。

## 六、范围之外（后续可做）

* 游戏自带的美术（`static/assets/story-card-art/` 57 张、剧情/UI 图标）没有纳入本次规整；
* `static/assets/mod-card-art/` 是**运行时缓存**（按内容 hash 命名，现有约 1.9 万个文件），
  改包后旧缓存会自然失效，不需要手工清理；
* 新增卡图走本规范：导出时就用 `viewBox="0 0 283.46 283.46"`，内容占 60% 居中，
  或者导出后跑一次 `normalize_card_art.py`。
