## 0. 先读这一节：数据步骤长什么样

### 0.1 步骤的两种写法

运行时取 op 的规则（`mod_runtime_v2.run_v2_step` 第 205-206 行）：

```python
op = step.get("op") or step.get("type")
params = step.get("params") if isinstance(step.get("params"), dict) else step
```

因此下面两种写法等价，且可以混用：

```json
{"op": "deal_damage", "target": "target", "amount": 8}
{"type": "deal_damage", "params": {"target": "target", "amount": 8}}
```

新数据一律用 `op` + 扁平参数；旧式 `type/params` 仍被接受（历史卡包与 `body` 里可能残留）。

### 0.2 两条执行路径（非常重要）

同一个 op 名可能被**两条不同管线**执行，参数支持程度略有差别：

1. **v2 运行时路径**：卡数据里的顶层步骤（`events.<hook>.steps[...]`）由 `mod_runtime_v2.run_v2_step` 直接执行。
   它自己实现了 `deal_damage` / `direct_damage` / `heal` / `draw_cards` / `gain_e` / `gain_m` /
   `add_status|remove_status|set_status` / `move_card` / `create_card` / `destroy_equipment` /
   `if` / `for_each` / `request_target` / `request_ui` / `deck_catalog_pick` / `modify_event_value` /
   `set_var` / `add_var` / `log`，其余 op 转发给引擎原子。
2. **引擎路径**：被引擎原子内部展开的步骤（`body` / `steps` / `effects` / `then` / `else` / 定时器效果等）
   由 `game_engine._run_effect_list` → `_atomic_<op>` 执行。
   例：`arctic:nuke` 的 `defer_game_over.body` 里的 `deal_damage` 走的是**引擎版** `_atomic_deal_damage`，
   所以只有引擎版才有的 `power_once` 生效；而顶层 `deal_damage` 用的是运行时版，`power_once` 不生效。

写卡时的经验规则：**顶层用运行时版参数；嵌套在引擎原子 body 里的步骤按引擎版参数写**，
两者取交集最安全（`target` / `amount` / `hits` / `log` 两边都有）。

### 0.3 战报（log）模板

- `"log": "……"` 字符串 = 自定义战报，支持占位符：`{target}` `{source}` `{amount}` `{count}` `{name}`（`{card}` 同 `{name}`），
  以及当前上下文 `vars` 里的任意变量名（如 `{total}`、`{absorbed_damage}`、`{hit_index}`）。
- `"log": false` = 不打印该步骤的战报；`"log": true` / 不写 = 用原子默认文案。
- 运行时版 `heal` / `gain_e` / `gain_m` 额外支持 `log_positive_only`：没有实际回复/获得时不打印。
- 引擎原子通用开关：`silent` / `no_log` / `hide_log`（各原子支持程度见 §6 表的“参数”列）。

### 1.1 被动声明块（Round 5–6 起：引擎只读卡数据的 `events`，不再读卡名）

这些键写在**卡数据**的 `events` 里，但它们不是"被派发的事件"，而是引擎在固定时机主动查询的**声明块**
（`engine_runtime_support.py` 里的 `*_EVENT` 常量就是键名）。没有声明的卡 = 没有该机制（第三方包回落见 §10）。

| 声明块 | 挂在哪 | 关键字段 | 语义 | 首用卡 |
|---|---|---|---|---|
| `on_card_targeted` | 装备卡 | `relation`(`any`/`self`/`teammate`/`friendly`/`enemy`)、`steps` | 装备所挂目标被"出牌选为目标"时派发（尖牙回血） | `sewers:vampire_fang` |
| `on_target_restrict` | 装备卡 | `from`(默认 `equipment_target`)、`to`(默认 `owner`) | 强制目标重定向（眼球：目标只能指向装备拥有者） | `void:eyeball` |
| `on_damage_absorb` | 装备卡 | `when`(`any`/`attack`/`direct`)、`target`、`cost`(`{"m":1}`/`{"e":2}`…)、`charge_to_hand`(`{"mode":"ceil_even"|"exact"}`)、`log` | 伤害吸收 + 转充能（魔法铜棒） | `void:magic_copper_rod` |
| `on_turn_start_choice` | 装备卡 | `id`、`cancellable`、`owner_is_turn_player`、`cost`、`when`、`control`(`select`/`player_picker`)、`choices[].{value,cost,steps}`、`steps` | 回合开始弹窗队列（扇子/精神分裂症）；`id` 同时是暂停 `purpose` | `void:fan`、`void:schizo` |
| `on_cost_refresh` | 任意卡 | `legacy_vars`、`reset` | 每次 `can_play_card`/`get_public_state` 前清账（动态改费） | `void:nut` |
| `on_create_copy` | 任意卡 | `steps` | 生成"复制体"时以副本为 `card`/`self` 运行步骤 | `void:magic_slime_ball` |
| `on_effective_status` | 任意卡 | `status`、`sources[]`(`custom_status`/`player_status`)、`combine`(`max`/`sum`)、`floor`、`visible`(`hide`/`cap`/`add`/`sub`) | 有效状态投影（剧毒=剧毒+中毒取最大） | `jungle:magic_poison_stinger` |
| `on_elixir_recovery` | 装备卡 | `elixir`、`overload`、`log` | 装备所挂目标回合开始的回能/超载光环（Round 8） | `vanilla:pincer` |
| `on_equipment_projection` | 装备卡 | `armor`/`max_elixir`/`max_magic`（生效时的增量）、`on_destroy`（默认 true）、`on_transform`（默认 true） | 封印挂起/恢复/销毁时的属性投影；置 false 表示该卡自己的 `equipment_destroy` 脚本负责补偿（Round 8） | `vanilla:disc`、`desert_cards_addition:cactus` |
| `on_play_summary` | 任意卡 | `suppress_detail_logs`、`suppress_play_log`、`plain_log`、`discarded_log` | 出牌摘要文案（模板支持 `{player}`/`{target}`/`{count}`）（Round 8） | `vanilla:chilli` |
| `events.<hook>.require` | 任意卡 | 与事件上下文逐键比对（数组＝其中之一）；`min_damage` 比对伤害量 | 声明式触发条件（Round 8） | `garden:avocado` |
| `on_response.resolution` | 反制牌 | `negate_bloom`、`negate_responded`、`exile_responded`、`log`、`halve_precision`、`clamp_responder_props`、`suppress_responder_untargetable`、`after_resolution`（步骤） | 反制结算期语义（Round 9；见 §12） | `vanilla:bubble`、`ocean:cucumber`、`ocean:nitro` |
| `status_aliases`（卡顶层键，不在 `events` 里） | 任意卡 | `role`、`canonical`、`aliases[]`、`legacy.{active,hits,max}` | 状态别名表 + 旧档字段折算（Round 9；例：邪眼/Nazar） | `vanilla:nazar` |
| `fallback_card`（卡顶层键） | 任意卡 | 卡 id 字符串 | 该卡的兜底生成卡由数据声明（Round 9，蛋白石 → 轻） | `bio:opal` |
| `property_caps`（卡顶层键） | 任意卡 | `{属性名: 上限}` | 该卡的属性上限；`card_prop_add` / `card_prop_set` / 读值 / 攻击加伤都先查这张表（Round 10） | `jungle:tomato` |
| `reset_properties`（卡顶层键） | 任意卡 | 属性名数组 | 离场（`reset_card_after_play`）时归零的属性（Round 10） | `jungle:tomato` |
| `engine_effect`（卡顶层键） | 任意卡 | 内建仪式名（如 `"yggdrasil"`） | 指名调用引擎里的整段仪式（数据步骤表达不了的流程；注册表见 §13.1）（Round 10） | `vanilla:yggdrasil` |

Round 10 之后，"引擎侧还剩什么卡知识"只剩三处（§13 逐条登记）；下面这些**语义 flag** 也已由卡数据声明：
`blocks_cheap_attacks`（木板）、`absorb_damage_with_power`（琥珀）、`dna_turn_transform`（DNA）、
`skip_legacy_snowball_replay`（雪球旧档守卫）；世界树之叶的可选阵亡目标由
`events.on_play` 里 `request_target.alive_only: false` 决定。

其它两处从 Round 5/6 起"由卡数据决定"的机制：

- **装备必须是拥有者目标**：卡 `flags` 加 `owner_target`（不再维护 56 项卡 id 表）。
- **2v2 组合选择目标**：卡 `flags` 加 `combined_choice_target`。
- **手上电荷**：卡 `flags` 加 `applies_hand_charge`（铜棒响应判定只读该标记）。
- **副目标列表**：出牌步骤参数写 `"secondary_target_key": "_desert_marble_targets"`（取代引擎里的卡名判断）。

Round 5 起的统一约定是 `flags` 里的 **`mark:<包>:<卡>`**（等价短名 `<包>:<卡>` 也认）：引擎只按标记比对，
不再比对卡 id 字面量。工具/图鉴把 `mark:*` 当标签显示，属预期。

## 2. 目标选择器（`resolve_v2_target`）

凡是“目标/对象”参数（`target`、`source`、`owner`、`cards`、`items`、`zones` 等）都走这套解析：

| 选择器 | 解析成什么 |
|---|---|
| `"source"` / `"self"` | 当前效果的发起者（`context.source_player`） |
| `"target"` | 若上下文里有 `wide_strike_targets` 列表 → 返回**该列表**（群体牌全体）；否则返回 `target_player`，缺省为敌方 |
| `"enemy"` | 显式选择的目标优先，否则 `_enemy_id(source)` |
| `"wide_strike_targets"` | 引擎 `_wide_strike_target_ids(source, card)`：横扫/群体牌本次真正打到的目标集合（尊重 `self_target` 与出牌时快照）。**群体牌推荐用它而不是 `all_enemies`** |
| `"all_enemies"` | `engine.get_all_enemies(source)`（2v2 下是敌方全体） |
| `"all_players"` | 全部座位 |
| `"all_others"` / `"all_except_self"` / `"everyone_else"` | 除自己外的全部座位 |
| `"friendly"` / `"self_team"` / `"all_friendlies"` | 同队玩家（`engine.team_of`） |
| `"teammate"` | 同队中除自己 |
| `"random_enemy"` / `"random_friendly"` / `"random_player"` | 随机（可被 RNG 覆盖强制指定） |
| `"random_selectable"` | 随机一个“当前可选”的目标（`_resolve_random_selectable`，尊重不可选中/隐形） |
| `"lowest_health_enemy"` | 生命最低的可选敌人（引擎 `_jurassic_lowest_selectable_enemy`；无则 `-1`） |
| `"equipment_target"` / `"equip_target"` / `"equipment_effect_target"` | 当前装备的 `effect_target`（装备指向谁） |
| `"equipment_owner"` / `"equip_owner"` | 当前装备的拥有者 |
| `"team_members"` / `"team_member"` / `"target_team_members"` | 目标所在队伍成员列表 |
| `"hand"` / `"deck"` / `"discard"` / `"exile"` / `"equipment"` | 自己的对应区域（`equipment` 返回装备上的卡实例列表） |
| `{"ref": "hand"\|"deck"\|"discard"\|"exile"\|"equipment", "target": <选择器>}` | 指定玩家区域 |
| `{"ref": "zone", "zone": "discard", "target": "enemy"}` | 任意区域（`zone` 可 hand/deck/discard/exile/equipment） |
| `{"ref": "card_by_instance_id", "instance_id": <值表达式>}` | 按实例 id 找牌实例（找不到 = `None`） |
| `{"ref": "equipment_by_instance_id", "instance_id": ...}` | 按实例 id 找装备对象 |
| `"current_card"` / `{"ref": "current_equipment"}` | 正在结算的牌 / 装备 |
| `"chosen_card"` / `"selected_card"` / `"choice_card"` | 玩家在本次选择里选中的牌（含“必须仍可选”检查） |
| `"last_created_card"` / `"created_card"` / `"last_copied_card"` | 上一步创建/复制的牌实例 |
| `"event_source"` / `"source_id"` / `"last_actor"` / `"damage_source"` | 触发事件的来源玩家 |
| `"choice_target"` / `"selected_target"` / `"chosen_target"` / `"event_target"` / `"target_id"` | 本次选择的目标玩家 |
| `{"ref": "player_id", "id": <值>}` | 直接把表达式求值成玩家编号 |
| `{"ref": "var", "name": "x"}` | 运行时变量 `vars["x"]` |
| 整数 `1` / `0` | 原样作为玩家编号 |
| 其它字符串 | 若 `vars` 里有同名变量则取变量值，否则原样返回（通常配合 `for_each` 的 `as` 使用） |
| 列表 | 原样返回（已经是目标集合） |

## 3. 值表达式（`eval_v2_value`）

任何“数值/文本”参数都可以写成表达式对象（`{"op": ...}`，也接受 `ref` / `type` 作为 op 的同义词）。

| 表达式 op | 参数 | 语义 |
|---|---|---|
| 数字 / 字符串 / 布尔 | — | 常量原样 |
| 列表 | — | 逐项求值 |
| `const` / `literal` | `value`\|`const` | 常量（用于显式包裹） |
| `var` / `temp_var` | `name`（或 `id`）、可选 `target`、`default` | 不带 `target` = 运行时临时变量；带 `target` = 该玩家的 `custom_vars` |
| `player_var` | `target`、`name`、`default` | 玩家自定义变量（等同 `var` + `target`） |
| `global_var` | `name`、`default` | `engine.global_vars` |
| `get` | `object`、`key`、`default` | 取字典键 / 列表下标 |
| `player_stat` / `player_property` | `target`、`stat`\|`property`\|`field` | 玩家属性（见下方 stat 取值） |
| `card_prop` / `card_property` | `card`、`prop`\|`property`\|`field` | 卡属性（见下方 prop 取值） |
| `equipment_prop` / `equipment_property` | `target`、`equipment`、`prop` | 装备属性 |
| `zone_count` / `hand_count` / `deck_count` / `discard_count` / `exile_count` / `equipment_count` | `target`、`zone`、`card_type`、`require_selectable`、`equipment_id` | 区域牌数（可按类型过滤） |
| `equipment_count_targeting` | `owners`、`effect_target`、`equipment_id` | 统计“指向某玩家”的装备数量 |
| `hand_full` | `target` | 手牌是否已满（布尔） |
| `status_count` / `visible_status_count` | `target` | 身上大于 0 层的状态数量 |
| `counter_cards_in_hand` / `counters_in_hand` | `target` | 手牌里反制牌数量 |
| `deck_top_ids` / `zone_top_ids` | `target`、`zone`、`count` | 区域顶部 N 张的 `instance_id` 列表 |
| `count` | `selector`\|`of`\|`value` | 目标集合的元素个数 |
| `add` / `sub` / `mul` / `div` / `min` / `max`（或 `+ - * /`） | `values`（列表）或 `a`、`b` | 四则/最值（`div` 除零返回 0） |
| `clamp` | `value`、`min`、`max` | 夹取 |
| `random` | `min`、`max` | 整数随机 |
| `random_choice` | `values`\|`options`\|`from`、`default` | 从列表/字典随机取一项 |
| `choice_value` / `choice_field` | `key`、`default` | 读本次选择返回的字段（如 `card_type`、`pick`） |

## 4. 条件（`check_v2_condition`）

条件写法：`{"op": "compare", "a": <值>, "operator": ">=", "b": <值>}`。

| 条件 op | 参数 | 语义 |
|---|---|---|
| `and` / `or` | `conditions`（或 `values`） | 全部成立 / 任一成立 |
| `not` | `condition`（或 `value`） | 取反 |
| `compare`（或 `eq/ne/gt/gte/lt/lte` 与 `== != > >= < <=`） | `a`、`b`、`operator` | 比较；`>`/`<` 走数值，`==`/`!=` 精确比较 |
| `card_has_tag` | `card`、`tag` | 卡上是否有该 tag（`instance_flags`） |
| `card_has_modifier` / `card_has_setup_modifier` | `card`、`modifier`\|`name` | 卡是否有该 `setup_modifiers` |
| `has_status` / `has_status_named` | `target`、`status` | 身上状态层数 > 0 |
| `has_tag` / `card_has_flag` | `card`、`tag`\|`flag` | 同 `card_has_tag` 的别名 |
| `damage_type_is` / `damage_type` | `type_name`\|`value`\|`damage_type`（`any`/`*` 表示任意） | 当前事件伤害类型是否匹配 |
| `target_selectable` / `player_selectable` | `target`、`allow_self` | 目标是否可被选中 |
| `zone_exists` / `card_exists` | `zone`\|`selector` | 该集合是否非空 |
| `var_compare` | `name`、`target`、`value`\|`b`、`operator` | 变量比较（在 `vars` 或玩家 `custom_vars` 里） |
| 其它对象 | — | 交给 `eval_v2_value` 求值后取布尔 |

## 5. v2 运行时原生 op（`mod_runtime_v2.run_v2_step` 直接执行）

### 5.1 `request_target`（运行时）

- 参数：无（从 `context.choice` / `current_action` 里取玩家）。
- 语义：把本次选择的玩家写进 `context.target_player`（同时写入 `vars.target_player`），供后续步骤的 `"target"` 使用。
- 示例：`{"op": "request_target"}`（前面通常配 `{"op": "request_card", ...}` 或反制响应的目标选择）。
- 用例：大量多目标牌的 `on_play` 第一段。

### 5.2 `deal_damage`（运行时版）

| 参数 | 默认 | 说明 |
|---|---|---|
| `target` | `"target"` | 目标集合（可用 `wide_strike_targets` / `all_enemies` 等） |
| `source` | `"source"` | 攻击者 |
| `amount` | `0` | 伤害量（值表达式） |
| `hits` | `1` | 段数（会被夹取到合法范围） |
| `inherit_extra_hits` / `use_card_extra_hits` | `True` | 是否叠加卡的追加段数（额外攻击） |
| `is_precision` / `precision` | `False` | 必中（卡自带 `precision` tag 时自动为真） |
| `precognition` | `False` | 若“本次攻击会暴击”则临时获得必中（不会持久） |
| `force_crit` / `no_luck_crit` | `False` | 强制暴击 / 不触发幸运暴击 |
| `crit_bonus_multiplier` / `crit_bonus_damage` | `1.0` / `0` | 暴击加成 |
| `ignore_untargetable` | `False` | 无视不可选中 |
| `on_hit` | — | 每段命中后执行一次的子步骤（有 `hit_index`） |
| `on_hit_once` | — | 每个被打到的玩家只执行一次的子步骤 |
| `on_crit` | — | 出现暴击段时执行一次（`last_crit_hits` 可用） |
| `log` | — | 战报；`false` 静音该次伤害行 |

- 语义：走 `engine.deal_attack_damage`，因此**会经过攻击伤害管线**（力量、裂变、暴击、必中、闪避等修正），
  结算后写 `last_damage`（总伤害）与 `last_positive_hits`（实际命中段数）。
- 示例：`{"op": "deal_damage", "target": "target", "amount": 8, "on_hit_once": [{"op": "status_add_named", "status": "arctic:frost", "amount": 5, "target": "target"}]}`
- 用例：`arctic:cryo_bomb`（8 伤 + 命中叠 5 霜冻）、`garden:kale`、`desert_cards_addition:date`。

### 5.3 `direct_damage`（别名 `deal_direct_damage`）

| 参数 | 默认 | 说明 |
|---|---|---|
| `target` | `"target"` | 目标 |
| `source` | `"source"` | 可以是选择器，也可以直接写**文本**（此时作为伤害来源名显示） |
| `source_text` / `source_name` / `label` | `"效果"` | 战报里的来源名 |
| `amount` | `0` | 每段伤害 |
| `hits` | `1` | 段数（循环执行 `_deal_direct_damage`，每段单独结算） |
| `damage_type` | `physical` | 伤害类型（见 `damage_types.py`） |
| `damage_tag` | — | 伤害标签（供 `damage_type_is` / 反制判定） |
| `inherit_extra_hits` / `use_card_extra_hits` | `False` | 是否叠加卡的追加段数 |
| `silent` 或整步 `"log": false` | — | 不打印逐段“受到N点X伤害” |
| `on_hit` / `on_hit_once` | — | 同 `deal_damage` |

- 语义：**不吃力量/裂变修正**的直接伤害，用于“效果伤害”。
- 示例：`{"op": "direct_damage", "target": "self", "amount": 2, "source_text": "血染色体", "hits": 1}`
- 用例：`bio:blood_chromosome`（每抽 1 张自伤 2）、`factory:lithium`、`bio:blood_sugar`。

### 5.4 `counter_pending_attack_damage`

- 参数：`ratio` / `multiplier`（默认 `0.5`）、`source`、`source_text`、`damage_type`、`damage_tag`、
  `mode` / `damage_mode`（`direct`（默认）或 `attack`/`physical_attack`）、`target`（`all_enemies`/`enemies` 特判）。
- 语义：把“本次受到的攻击伤害”的 `ratio` 比例反弹/再结算一次；输入来自上下文
  `first_hit_damage` / `first_damage` / `incoming_damage_parts[0]`。
- 示例：`{"op": "counter_pending_attack_damage", "ratio": 0.5, "mode": "direct"}`
- 用例：`desert_cards_addition:salt`（沙子反击）。

### 5.5 `heal`（运行时版）

- 参数：`amount`、`target`（默认 `"source"`）、`log_positive_only`（没实际回复就不打印）。
- 语义：按目标逐个 `heal()`，按**实际回复量**打印（`{amount}` = 实际回复量）。
- 示例：`{"op": "heal", "target": "all_friendlies", "amount": 20}`
- 用例：`jurassic:azalea`、`sewers:basil`、`bio:blood_sugar`。

### 5.6 `draw_cards`（运行时版）

- 参数：`amount`（或 `count`，默认 1）、`target`（默认 `"source"`）、`silent`/`no_log`。
- 语义：抽牌并走 v2 抽牌钩子（`_draw_cards_with_v2_hooks`）；`{amount}` = 实际抽到的张数。
- 示例：`{"op": "draw_cards", "target": "self", "amount": 2}`
- 用例：`garden:missile`、`jurassic:acid`。

### 5.7 `gain_e` / `gain_m`（运行时版）

- 参数：`amount`、`target`（默认 `"source"`）、`log_positive_only`。
- 语义：获得/失去 E（`gain_e`，负数直接扣）或 M（`gain_m`）；`{amount}` 是名义值，`{gained}` 是实际获得量。
- 示例：`{"op": "gain_e", "amount": 2, "target": "self", "log": "{target}获得{amount}E"}`
- 用例：`bio:blood_knife`、`bio:high_yield_bond`、`desert_cards_addition:cactus`。

### 5.8 `add_status` / `remove_status` / `set_status`（运行时版）

- 参数：`status`（或 `id`）、`amount`（`remove_status` 用 `stack`）、`target`（默认 `"target"`）。
- 语义：加层 / 减层 / 设为固定层数，带免疫与状态定义（`_apply_status`，mod 自定义状态也走这里）。
- 示例：`{"op": "add_status", "target": "target", "status": "fire", "amount": 1}`
- 用例：`desert_cards_addition:dizzy`、`factory:sawblade`（加状态）、`vanilla:pill`（`remove_status`）。

> 命名的其它写法：`status_add_named` / `status_remove_named` / `set_status_named`（引擎原子，支持 `statuses` 列表）、
> `poison` / `burn` / `toxic` / `apply_poison` / `apply_burn` / `apply_toxic`（`add_armor`/`gain_armor` 同理）。

### 5.9 `move_card` / `create_card` / `destroy_equipment`

- `move_card`：`card`（选择器，默认 `current_card`）、`to`/`zone`（默认 `discard`）、`owner`（默认 `source`）。
- `create_card`：`card_id`/`id`、`to`/`zone`（默认 `hand`）、`target`（默认 `source`）；未知卡 id 会退化成错误卡占位。
- `destroy_equipment`：`target`（默认 `"target"`）、`equipment`（选择器）。
- 用例：`factory:fragment`（造碎片）、`jungle:maple`（给牌）、`void:satan_cross`（摧毁装备）。

### 5.10 `if`

- 参数：`condition`（或 `cond`）、`then`、`else`。
- 语义：**运行时版 `if` 有 `else`**；引擎版 `if` 只有 `then`（要分支请用 `if_else`）。
- 示例：
  `{"op": "if", "condition": {"op": "compare", "a": {"op": "last_damage"}, "operator": ">", "b": 0}, "then": [ ... ], "else": [ ... ]}`

### 5.11 `for_each`

- 参数：`items`（或 `targets` / `list`）、`as`（或 `var`，默认 `item`）、`steps`（或 `body`）。
- 语义：对集合逐项执行 body，循环变量写入 `vars[as]`；每轮上限 `FOR_EACH_LIMIT = 200`。
- 注意：**UI 挂起（选择窗口）会打断 `for_each` 游标**——需要在每轮里弹选择时，请在引擎原子里做
  （`for_each_list`）或用 `deck_catalog_pick`（它的续跑状态由运行时保存）。
- 示例：`{"op": "for_each", "items": {"ref": "hand", "target": "self"}, "as": "c", "steps": [ ... ]}`
- 用例：`void:cicada_3301`、`void:magic_black_hole`。

### 5.12 `request_ui`

- 参数：`component`（内联组件对象）或 `component_id`（注册表 id）、`target_player`（默认 `source`）、
  `save_as`（默认 `ui_result`）、`timeout_ms`、`on_cancel`（步骤列表）。
- 语义：抛出 UI 暂停，把 `component` 下发给客户端；玩家操作结果写进 `vars[save_as]`（用
  `{"op": "choice_value", "key": "card_type"}` 读取）。
- 示例（`factory:mechaantennae`）：
  `{"op": "request_ui", "save_as": "mecha_antennae_type", "component": {"type": "modal", "title_cn": "机械触角", "controls": [{"id": "card_type", "type": "select", "options": [{"value": "thorn", "label_cn": "攻击牌"}]}], "buttons": [{"id": "confirm", "role": "confirm", "label_cn": "确定"}]}}`

### 5.13 `deck_catalog_pick` / `deck_catalog_pick_resume`

- 参数：`targets`（默认 `all_selectable`）、`source`、`shuffle`（`"each"` 洗牌，`false`/`"none"` 不洗）、
  `pick`（每个牌堆选几张，默认 1）、`save_as`、`title`、`title_en`、`log`。
- 语义：先按 `shuffle` 洗目标牌堆，再逐堆弹出“从牌堆选 1 张加入手牌”的窗口；
  **续跑状态由运行时保存**，因此可以跨 UI 暂停（`for_each` 做不到）。
- 示例（`void:cicada_3301`）：
  `{"op": "deck_catalog_pick", "targets": "all_players", "shuffle": "each", "pick": 1, "title": "选择1张牌加入手中", "log": "{source}因蝉3301从{target}的抽牌堆获得1张牌"}`

### 5.14 `modify_event_value`

- 参数：`mode` / `operator`（`set`（默认）/`add`/`+`/`sub`/`-`/`mul`/`*`/`div`/`/`/`min`/`max`）、`value`（或 `amount`）。
- 语义：改写 `event_value`（后续用 `{"op": "event_value"}` 读取），常用于“受到伤害 ×2”类反制。
- 示例：`{"op": "modify_event_value", "mode": "mul", "value": 2}`

### 5.15 `set_var` / `add_var`

- 参数：`name`、`value`。
- 语义：写/加**运行时临时变量**（`context.vars`），供后续步骤 `{"op": "var", "name": "x"}` 使用。
- 示例：`{"op": "set_var", "name": "nuke_e", "value": {"op": "player_property", "target": "self", "property": "elixir"}}`
- 用例：`arctic:nuke`（把当前 E 存起来，稍后按 E 数循环）、`void:magic_black_hole`。

### 5.16 `log`

- 参数：`message`（或 `text` / `msg`）、`amount`（值表达式，供 `{amount}` 用）、`target`。
- 语义：打印一行自定义战报，支持 §0.3 的占位符。
- 示例：`{"op": "log", "message": "{source}的龟背竹使{target}回复{amount}H", "amount": {"op": "last_damage"}}`

## 11. 写作规范：引擎只认声明（Round 5–7）

给卡包作者和后续重构者的四条硬规则。**违反其中任何一条，都会让"引擎不认识卡"的前提失效。**

1. **卡片行为写数据，不写卡名**。引擎里的合法写法只有三种：
   `flags` 里的 `mark:<包>:<卡>` 标记、`events` 里的声明块（§1.1）、以及 `events.*.steps` 里的 v2 步骤。
   新增卡时**不要**在引擎里加 `if card.def_id == …` / `_card_has_mark(card, '<包>:<卡>')` 分支——
   这正是 Round 5–7 一路在清理的东西（清单与分类见 `.codex-tmp/round7/rd7.md`）。
2. **同一份规则只写一遍**。选牌过滤器同时驱动候选集、提交校验和卡级 `play_requires`；
   资源代价同时驱动"能不能弹窗"和实际扣费。重复写第二份必然漂移。
3. **时点优先用现成通道**。出牌期用 `on_play`；装备被动用 `on_equipment_trigger` / `on_*_turn_start`；
   受伤后反应用 `on_damage_taken`；响应窗口用 `on_response`（`negates_damage` 可声明是否取消伤害）；
   延迟用 `timed_effect`；"本回合每次出牌后"用 `register_play_listener`。
   只有当语义确实无法用上面任一通道表达时，才新增声明块，并同步登记
   `mod_spec_v2._CORE_LOGIC_OPS`、`mod_runtime_v2.ADVANCED_ATOMIC_OPS`、`atomic_registry.EXTRA_PUBLIC_OPS`。
4. **旧名只在登记表里保留一次**。`ATOMIC_OP_ALIASES`（12 条）与 `_EFFECT_ALIASES`（90 条）是唯一的旧名入口；
   新增别名要能说清"谁还在用"（Round 7 的审计脚本：`.codex-tmp/round7/rd7_registry_audit.py`）。

## 12. 如何把新机制数据化（写作规范 + 例子）

这一节写给"想把引擎里的某条按卡分支搬到数据里"的人（Round 8/9 就是按这套流程做的，共清掉 211 处）。

### 12.1 四步流程

1. **先分类，再动手**。用 `python .codex-tmp/round8/rd8_classify2.py` 生成 A/B/C 清单
   （A＝按卡分支，B＝类体常量/数据键，C＝死代码）。A 类逐处判断下面三种命运：
   **已死（删）** / **可数据化（加声明）** / **必须保留（写进 §10 式登记）**。
2. **优先"删"**。如果数据已经声明了同一件事（例如卡数据已有 `on_owner_turn_start`），
   引擎里的 `if mark == ...` 就是不可达兜底：先在**沙箱副本**里把分支体换成
   `raise RuntimeError('POISON')` 跑场景（毒化实验），0 命中才删。
3. **能挂现成通道就挂现成通道**：`on_play` / `on_owner_turn_start` / `on_equipment_trigger` /
   `on_damage_taken` / `on_response` / `on_card_used` / `timed_effect` / `register_play_listener`。
   只有语义确实无处可挂，才新增声明块（下一节）。
4. **等价性用 A/B 沙箱证明**：`python .codex-tmp/round9/rd9_baseline.py`（把本批改动反向打回，
   得到"旧代码+旧数据"副本）+ `python .codex-tmp/round9/rd9_ab.py run before|live <探针.py>`
   + `python .codex-tmp/round9/rd9_cmp.py <before.json> <after.json>`。**0 差异**才算完成；
   有差异就逐字段定位，而不是"看起来一样"。

### 12.2 什么时候该加新声明块

| 症状 | 推荐做法 | 例子（本仓库） |
|---|---|---|
| 引擎在**固定时点**主动查询"这张装备要不要做点什么" | 加 `events.<时点>` 声明块，引擎只做"遍历+判条件+跑 steps" | `on_elixir_recovery`、`on_equipment_projection` |
| 需要的是**"哪张卡"这一位信息**（其余逻辑通用） | 加语义 `flags`（不要用 `mark:` 之外的卡名判断） | `damage_hit_temp_swift`、`spikeball_boost` |
| 只是文案/日志不同 | 把模板放进数据（`log` / `on_play_summary` / `return_log`） | `on_play_summary`、`add_tag.return_log` |
| 结算顺序里的一段特判（免疫短路、回滚、放逐） | 加"结算期字段"，引擎按字段决定分支 | `on_response.resolution.*` |
| 状态有多个别名 + 旧档字段 | 加 `status_aliases`，引擎按表读写 | `vanilla:nazar` |
| 需要的卡是**引擎内建产品**（不是某张卡的行为） | 类体常量表 + 白名单常量（B 类，不进卡数据） | `SETUP_PRODUCT_CARDS`、`BUILTIN_SETUP_CARD_IDS` |

### 12.3 例子 1：`on_response.resolution`（Round 9）

反制牌的"结算期语义"全部写在自己的 `on_response` 里，引擎只读字段：

```json
{"on_response": {
  "steps": [{"op": "player_prop_add", "target": "self", "property": "dodge", "amount": 1}],
  "resolution": {
    "halve_precision": true,
    "clamp_responder_props": ["dodge"]
  }}}
```

字段含义：`negate_bloom`（所响应的技能牌失效）、`negate_responded` / `exile_responded`（所响应牌
失效 / 结算后进放逐区，配 `log` 文案）、`halve_precision`（被精准攻击时改为减半结算）、
`clamp_responder_props`（响应中获得的属性在结算后压回响应前的值）、
`suppress_responder_untargetable`（结算期临时解除自身的"不可选中"，让所响应牌能正常结算）、
`after_resolution`（结算后的步骤，例如黄瓜的 +1 层不可选中）。

### 12.4 例子 2：语义 flag（Round 7–9 的标准做法，30+ 张卡）

```json
{"id": "jurassic:tooth", "flags": ["non_stackable", "mark:jurassic:tooth", "heal_redirect_to_attack"]}
```

```python
# 引擎：只认 flag，不认卡名
tooth = next(self._active_equipment_targeting_flag(player_id, 'heal_redirect_to_attack'), None)
```

判定与日志里的卡名一律用 `self._equipment_card_label(eq)` / `card.name_cn` 取，不再写字面量。
**副作用要在 PR 里说清**：第三方包只抄卡数据、不抄 flag，会静默失去该被动（§10 第 9 条）。

### 12.5 例子 3：把"引擎内建集合"固定在 B 类

引擎确实需要知道的卡（客户端契约、内建产品、回落表）放**类体常量**，并在报告里写明"为什么不是卡数据"：

```python
class GameEngine:
    BUILTIN_SETUP_CARD_IDS = frozenset({'ManaOrb', 'Light', 'Dust', 'Yggdrasil'})
    SETUP_PRODUCT_CARDS = {2: 'ManaOrb', 3: 'Light', 8: 'Yggdrasil', 9: 'Dust'}
```

`static/js/game.js` 按这些 id 渲染开局事件选择 UI，改 id 就是改客户端契约——这类常量属于"引擎内建表"，
分类器记 B，不计入按卡分支。
