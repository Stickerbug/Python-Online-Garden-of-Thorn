# 休闲花园 · 2048（使用与维护说明）

内测功能。本文只讲**怎么用、怎么配、边界在哪**；规则细节见卡面/游戏内说明，
原子与工具链见 `docs/引擎原子与数据步骤清单.md`。

## 1. 入口与权限

| 项 | 值 |
|---|---|
| 主页面入口 | 「单人训练场」下面的 **休闲花园**（砂金色，`static/css/style.css` 的 `.btn-leisure`） |
| 直达地址 | `/minigame/2048` |
| 权限 | **服务端角色表** `user_roles.role_type ∈ {staff, admin}`；未登录 401、无权限 403 |
| 开关 | 环境变量 `GTN_MINIGAME_2048=0` 可整体关闭（入口与接口一起） |

按钮只对通过判定的账号渲染，但**直达 URL 与所有接口仍由服务端拦**（`app.py` 的
`_minigame_2048_guard`），不存在"藏按钮"式权限。

## 2. 玩法与规则

标准 4×4 2048：90% 出 2 / 10% 出 4、同值合并、同一次操作新合成的方块不再合并、
只有棋盘变了才生成新块。方块显示**稀有度英文名**（可在设置里叠加数值）。
17 档色板是这份游戏的固定配置，与主题无关。

前后端同源：`minigame_2048.py`（服务端）与 `static/js/minigame_2048_core.js`（客户端）
必须给出相同的棋盘、分数、随机状态（`tests/test_minigame_2048_parity.py` 对拍）。

## 3. 存档 / 同步 / 排行榜

* 一局 = `(种子, 操作串)`；库里只存**检查点 + 增量**，验证时从检查点重放。
* 分数由**服务端重放**得出，客户端自报分数/棋盘只用于对拍，对不上直接拒绝并留审计。
* 只有相对该局已验证进度的**真实增长**才写新记录（刷新 14 天窗口）；重复上传同一分数、
  只读、无加分移动都不会续期。
* 排行榜：`GET /api/minigame/2048/leaderboard?window=14d|all`，每账号一行，
  总分降序 → 最高方块降序，两项都相同并列。
* 离线自开的局：客户端带 `new_game + seed + 完整操作` 补传，服务端从起点重放后
  以 `source='offline'` 入库（审计里记 `adopt_client_game`）。

## 4. 每周冠军荆露（结算）

| 项 | 默认值（`minigame_2048_service.py` 顶部常量） |
|---|---|
| 结算时点 | **UTC+8 每周一 00:00**（`FEATURE_EPOCH_CZ` 之后才结算，不追发启用前奖期） |
| 榜单窗口 | 该时点往前 **14×24 小时**内**已验证入库**的成绩，每账号取最好一条 |
| 奖池 | `CHAMPION_POOL = 300` 荆露 |
| 门槛 | `CHAMPION_MIN_ACCOUNTS = 3` 个有效账号，否则记 `skipped` 与原因 |
| 并列 | 平分 300；整数部分均分，余数按稳定账号 ID 顺序发（不改变并列排名） |

实现要点：奖期行（`minigame_2048_periods`）**先在事务里落快照**，荆露走现有
`users.thorn_dew_free` + `user_currency_transactions` 账本，`minigame_2048_rewards`
的 `UNIQUE(period_key, user_id)` 保证多进程/重启/重试**不会重复发放**；
晚到的补传不会改写已完成的奖期。结算线程随进程启动（`ensure_minigame_2048_settlement_worker`），
错过时点会按**原截止时间**补做。

## 5. 离线与缓存

* `/minigame/2048/sw.js` 是**局部** Service Worker（scope 只有这一页）：
  只缓存页面外壳 / CSS / JS / 图标，**不缓存** `/api/*`、登录响应或账号资料。
* 联网优先：收到真实 401/403 时页面走身份/权限处理，不会用缓存假装成功。
* 离线时照常能玩（本地先跑，不等服务器），同步在恢复后自动重试（指数退避）。
* 加第二个小游戏前，需要把 SW 的 scope 统一到 `/minigame/`（现在按单个游戏隔离）。

## 6. 大厅 / 聊天 / 邀请

* 进入小游戏后大厅里显示 **「休闲 · 2048」** 徽章；默认**可被邀请**。
* 小游戏内的「拒绝对局邀请」偏好**在服务端邀请处理处**执行（不是把按钮变灰）。
* 小游戏页走一次正常 `login` 握手（方案 A）：同账号会**接管**大厅标签页；
  返回大厅会重新登录。要双开需要服务端的"轻量会话"方案（尚未实现）。
* 聊天按**方案 (a)**：小游戏内挂的是**大厅聊天**（与多人游戏同一条，
  服务端把 `status='minigame'` 也算进大厅聊天接收名单）；故事聊天仍是独立频道。
  聊天面板在右下角悬浮按钮里，默认收起；限流/禁言/风险拦截与转义全部沿用服务端。

## 7. 防作弊边界（明确声明）

* 服务端重放能保证：**非法局面、断裂操作、改分、归属错误**进不了榜。
* 重放**不能**证明：没有复制存档、没有挑种子、没有预知随机或用求解器。
  这是本项目接受的取舍（离线补传通过验证后同样具备排名与领奖资格）。
* 客户端哈希/时间戳不作为安全边界；排行榜时间一律用**服务器时间**。
