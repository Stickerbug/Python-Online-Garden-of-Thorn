# 故事模式数据版本与迁移

目标：故事模式数据（进行中的旅程、手动存档、通关进度、图鉴）应尽可能保留，
不再因内容代码更新而被直接清空。

## 两层版本

- `STORY_RULES_VERSION`（`story_mode.py`）：规则契约版本。只有会影响现有旅程的
  生成、校验或结算语义的改动才允许递增。
- `STORY_CONTENT_VERSION`：展示/内容指纹版本。名称、描述、图片、稀有度等
  展示内容变化会改变它，但**不应**影响正在进行的旅程。

展示层更新时，服务器启动阶段会为规则兼容的旧旅程重新打上新展示版本（relabel），
玩家可以直接继续；不会删除任何行。

## 规则变更时的流程（每次只提示一次）

1. 修改故事模式规则前，先检查本文件与 `story_content_versioning` 的守护测试。
2. 如果改动可能使旧旅程的生成/结算不一致，把旧旅程视为不兼容：
   - 保留旧旅程、手动存档、动作记录与通关进度，不删除；
   - 旧旅程保持旧 `content_version`，由现有 fail-closed 流程要求玩家显式替换，
     而不是被后台静默覆盖；
   - 通关进度、图鉴和成就照常保留。
3. 为 `STORY_RULES_VERSION` 的新值在 `STORY_RULES_CHANGELOG` 中补一条说明
   （是否与上一版本兼容、改动摘要），否则守护测试会提示一次并失败。
4. 如果改动与旧版本兼容（例如只影响新生成内容），为旧旅程执行 relabel 后放行。

数据库启动迁移入口：`db.py::_migrate_story_data_for_contract_if_needed_conn`。
