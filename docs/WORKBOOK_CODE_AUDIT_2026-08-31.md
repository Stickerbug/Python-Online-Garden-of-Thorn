## 1. 判定规则

本审计区分五种结论：

| 结论 | 含义 |
|---|---|
| 正确 | 工作簿条目已由当前代码覆盖，未发现影响玩法的结构差异 |
| 偏差 | 双方都有实现，但名称、数值、时序、范围或流程不同 |
| 未实现 | 工作簿存在有效设计，当前代码没有对应内容 |
| 暂缓 | 工作簿或已确认范围明确要求本轮不实现 |
| 待确认 | 不能只凭表格安全决定，应在对应任务实施前再次确认 |

“名称存在”不等于“功能正确”。本次先做目录、规则形状与已知数值差异审计；后续 P2-02/P2-06 会把单元格来源固化进规范化内容模型，并对费用、升级、标签、效果和意图做自动逐字段校验。

## 4. 可定位差异

### 4.1 爬塔赐福设计

- 已覆盖：`B2:B9` 八项效果，和 `story_content.py:788-845` 的八个定义一一对应。
- 未实现：`B10`“拥有 3 次无视路线选择下一层的机会”。当前故事状态、路线动作和地图 UI 中均无次数字段或无视路线动作。
- 结论：P2 内容模型需保留该来源，但在补齐权威路线消耗、存档字段和协作语义前不得只加显示文本。

### 4.2 爬塔卡牌设计

- 工作簿有 152 个具名内容行；当前中文名称直接命中 96 行。
- 未实现：`B102`“雏菊”。
- 已规范收录：`B103:K157` 的 55 张魔法师具名牌，以及 `B158:F158` 的“电击伤害”术语。所有条目当前均为 authored/deferred，只有在对应权威执行器和测试完成后才会晋升到可玩 `STORY_CARDS`。
- 用户勘误：`B104`“魔法橙子”为5D，升级后7D；`B143` 改名“魔法蜂蜡”；`B152` 改名“魔法电容器”。勘误值优先于冻结工作簿原单元格文本，并保留原单元格来源用于审计。
- `B133`“魔法电池”与 `B152`“魔法电容器”、`B136`“魔法蜂蜜”与 `B143`“魔法蜂蜡”使用各自稳定 ID，不能按旧重名合并。
- 普通的花花目录基本存在，但数值/升级逐字段一致性仍归 P2-06；本审计不把名称命中误报为全部数值已冻结。

### 4.3 角色设计（先不做）

- `A1:B1` 普通的花花：当前单人故事主角色；继续作为第一实现基线。
- `A2:B2` 轨道使：保留目录与未来解锁位，本轮暂不实现，显示统一未就绪提示。
- `A3:B3` 召唤师：保留目录与未来解锁位，本轮暂不实现，显示统一未就绪提示。
- `A4:B4` 魔法师：纳入本轮，依赖上一节 55 个具名内容行和魔力系统。
- `A5:B5` 邪术师：保留目录与未来解锁位，本轮暂不实现，显示统一未就绪提示。
- 尚未实现的角色显示统一提示“这名角色还没准备好呢\n请期待开发组更新”，且服务端拒绝创建旅程。
- 解锁链以执行计划为准：普通的花花→魔法师→轨道使→召唤师→邪术师；未实现角色不会因为满足进度而提前开放。
- 魔法师的首个解锁条件为：普通的花花以任意难度通关当前完整旅程（全部阶段）；仅完成第一阶段不计入解锁。

## 5. 对后续任务的约束

1. P1 只修已确认的对局 Bug 与平衡项；五名角色的完整实现按 P2/P3 内容契约与角色批次推进，不与 P1 修复混做。

4. P2-06 至少自动核对中文名、费用、稀有度、描述、升级、标签、效果、敌人生命/意图、事件选项、称号价格/颜色与战斗组合。

6. 已批准的新计划优先于旧工作簿数值，但每一处覆盖都必须在执行计划与更新日志中留下来源和原因。
