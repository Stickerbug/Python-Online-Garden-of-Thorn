# 休闲花园 · 小游戏接入规范（2026-09-22）

以后加一个小游戏，需要的东西都已经收在下面这几处；**不用**再去改 presence 白名单、
邀请逻辑、返回按钮或大厅排序。

## 一、服务端：一份注册表

`minigame_registry.py` 是"有哪些小游戏"的唯一事实来源：

```python
MINIGAMES = {
    'suika': {'key': 'suika', 'title': '合成大花花', 'path': '/minigame/suika', 'invite_ready': True},
}
```

加一个小游戏 = 在这里加一行。用它拿到的东西：

- `is_minigame(game_key)`：`on_minigame_presence` / `on_minigame_leave` 的白名单（未登记一律拒绝）；
- `path_of(key)` / `with_from(path, from_key)`：列表页与小游戏页链接，自动带来源标记；
- `minigame_hub_back_href(from_key)`：休闲花园返回按钮的目标，**只认白名单**（`lobby` → `/?enter_lobby=1`，其余 → `/`），避免开放重定向。

## 二、客户端：一个通用外壳

`static/js/minigame-presence.js`（经典脚本，暴露 `window.GtnMinigamePresence`）负责：

- socket 连接 → `login` → `minigame_presence {game: <gameKey>}`（在线状态，大厅里显示"休闲花园"）；
- 收到 `invite_received` 时显示邀请条（可指定元素 id），接受前先跑 `beforeAccept()` 保存本地进度，
  然后 `accept_invite` + 跳到 `/?from_minigame_invite=1`（主页面会自动接上这一局）；拒绝则 `decline_invite`；
- 页面关闭时 `minigame_leave`（状态回到大厅）；
- 账号级"拒绝对局邀请"开关：`GET/POST /api/minigame/prefs`（`decline_invites`，所有小游戏共用）。

页面接入（三行）：

```html
<script src="/static/vendor/socket.io.min.js"></script>
<script src="/static/js/minigame-presence.js"></script>
<script>GtnMinigamePresence.attach({ gameKey: 'suika', nickname: CONFIG.username,
  beforeAccept: async () => { saveLocal(); } });</script>
```

2048 目前仍是自己页面内联的实现（功能等价），后续可以迁移到这一份通用外壳，二选一即可。

## 三、大厅联动

- **位置**：`get_lobby_list()` 的排序键是"观战者最后 + 角色排序 + 昵称"。
  正在玩小游戏的人**不再被单独分组**，所以在大厅里就停在"离开大厅时"的位置；
  观战者按用户要求仍然排最后。
- **来处**：从大厅进休闲花园走的链接带 `?from=lobby`，从首页走 `?from=home`；
  休闲花园与小游戏页把来源透传，返回按钮按 `minigame_hub_back_href()` 走。
  带 `?enter_lobby=1` 回到主页时，`game.js` 会自动点一次"进入大厅"并把参数从地址栏抹掉，
  这样返回的落点是大厅本身，而不是停在主页登录界面。
- **按钮位置**：大厅页脚顺序 = 返回主页、设置、休闲花园（休闲花园在最右）。
