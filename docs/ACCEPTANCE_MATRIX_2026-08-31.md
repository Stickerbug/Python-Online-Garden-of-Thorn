# Garden of Thorn 本轮修改验收矩阵与提交拆分

> 版本：v1
> 冻结日期：2026-08-31
> 上位计划：`docs/CHANGE_PLAN_2026-08-31.md`
> 适用任务：P1-01 至 P8-08

## 1. 使用规则

1. 每个任务先满足本表的前置依赖，再开始改变权威规则。
2. “测试层级”是最低要求，不是上限；触及多个模式时必须覆盖所有受影响模式。
3. 一个提交只承担一个可独立解释、可独立回滚的规则单元。数据库迁移、权威结算、前端和运营工具不得无边界混在同一提交。
4. 所有数据库变更只允许前向、可重复的 additive migration；回滚以关闭写入口和恢复旧读路径为主，不执行破坏性降级。
5. 内容语义变化必须提升对应 `content_version`；旧故事状态按 `DATA_COMPATIBILITY_POLICY_2026-08-31.md` 只读保留。
6. 所有奖励、花阶、信誉、举报和关联结论必须使用服务端权威值与唯一业务 ID。
7. 计划中的“提交组”是审查边界，不代表立即执行 Git commit；只有通过该组闸门后才允许提交。

## 3. 回滚类型

| 代号 | 回滚点 |
|---|---|
| R-FLAG | 关闭新入口或新结算开关，保留新表和历史数据 |
| R-RULE | 回退单一权威规则提交；若已产生新故事数据，保留新内容版本并停止新写入 |
| R-CONTENT | 恢复旧内容版本为新建旅程默认值，新版旅程只读，不原地降级 |
| R-DB | 停止使用新增列/表，不删除已写数据；修复后前向迁移 |
| R-SEASON | 停止新排位写入并冻结新赛季，旧赛季和已结算流水不重算 |
| R-UI | 回退前端/模板并提升静态资源版本，不回滚权威数据 |
| R-OPS | 撤回公告或关闭管理入口，审计记录永久保留 |

### P6-07 自动化硬闸门

- `suspected`、`probable`、`confirmed` 均由服务端事件或定时重算自动产生，不等待 Staff/Admin 点击批准。
- 自动确认必须总分至少 90、至少两类独立信号，且至少一类为设备或持续行为；IP 类信号单独永不确认。
- 模糊花阶只比较 50 分区间，并仅作为低权重行为信号；精确花阶不能单独建组，也不能在管理页以外对外暴露。
- `probable` 只能限制重复对手/短局/新人奖励，不能直接共享信誉；只有 `confirmed` 进入组级信誉和新人权益规则。
- 每次自动状态转移必须保存规则版本、总分、命中类别、脱敏理由和唯一重算 ID；同一输入重复执行结果相同且不新增重复流水。

## 13. 更新日志合并分组

最终 `CHANGELOG.txt` 只按玩家可理解的主题合并：

1. 对局错误修复与规则一致性（P1-01 至 P1-04）。
2. 卡牌、天赋与故事规则平衡（P1-05 至 P1-12）。
3. 故事内容、角色、地图、存档与界面（P2-P3）。
4. 公告、投票与运营能力（P4）。
5. 排位模式、新赛季与花阶规则（P5）。
6. 信誉、举报、自动关联账号及申诉（P6）。
7. 新人保护、对局奖励和防刷（P7）。

测试数量、内部函数名、数据库表名和仅用于防回归的技术细节不逐项写入玩家更新日志；安全修复只描述可公开的结果，不公开可绕过阈值。
