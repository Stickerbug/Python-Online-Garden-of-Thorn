### 怎么读这张表

- **原子**列 = op 名 + 执行路径徽标：
  `运行时` = `mod_runtime_v2.run_v2_step` 直接执行；`引擎` = `game_engine._atomic_*`；
  `表达式` / `条件` = 只能出现在取值表达式 / 条件位置；`时点` = 卡数据 `events` 里的声明块键；
  `别名→X` = 先被别名表改写成 X 再执行（`ATOMIC_OP_ALIASES` 或 `_EFFECT_ALIASES`）。
  `⚠无实现` = 白名单里有登记、但引擎与运行时都没有实现，写进卡数据会报 `unsupported v2 op`。
- **参数**列 = 实现里真正读的键（`params.get('k', 默认值)` / `expr.get('k')` / `params['k']`）：
  `默认` 取源码里的默认值；`可写表达式` = 该参数被 `eval_v2_value` / `_eval_int` / `_step_text_value` 包着求值；
  两条执行路径默认值不同时显示 `A / B ⚠`（全部清单见附录 C）；
  `共享实现 _helper` = 参数是在共享助手里读的，两条路径同一份语义。
- **语义**列抄自清单文档；抽不到结构化语义的原子标 `未验证：…`，不猜。
- **真实用例** = 卡数据里首次出现该 op 的卡 id + 该卡里最短的一步 JSON 片段；
  嵌套步骤列表缩成 `[…N 步…]`、条件缩成 `{…}`，只保留能说明用法的骨架。
- **使用次数** = 多少张卡 / 多少步（步骤级扫描；只出现在表达式或条件里的 op 记 0）。
- **扩展点** = 源码里能判定的扩展方式（表达式参数 / 多目标集合 / `body` 子步骤 / `on_hit` 回调 /
  `log`·`silent` 开关 / 步骤门控）。判定不了的不写，宁缺毋滥。
- 所有**非控制流**步骤都能加步骤门控 `condition`/`unless`（§14.1）；控制流 op 用 `run_if`/`unless`。

## 附录 F：怎么写新原子 / 新参数

沿用清单文档 §12（把新机制数据化）与 §14（步骤级门控与通用参数）：

1. **先定语义与参数**，再动代码：op 名、每个参数的默认值、战报行为、未知参数怎么处理；
   能写成「数据步骤序列」的优先改数据，不要新增引擎原子（§12.1）。
2. **两条路径同步实现**：`mod_runtime_v2.run_v2_step`（顶层步骤）与 `game_engine._atomic_<op>`
   （嵌套 body / 定时器 / 旧写法走这条）；同名参数默认值必须一致，否则按 §5.4 改名或统一。
3. **能挂现成挂点就别造新词**：`on_play` / `on_owner_turn_start` / `on_equipment_trigger` /
   `on_damage_taken` / `on_response` / `timed_effect` / `register_play_listener`（§12.1 第 3 步）。
4. **参数按通用约定写**：数值/文本参数直接吃取值表达式（§14.2 列出了已覆盖的 op 与参数键）；
   步骤门控用 `condition`/`unless`（控制流 op 用 `run_if`/`unless`，§14.1）；
   默认文案用 `log`，关掉用 `log: false` / `silent: true`（§14.3）。
5. **别名只加不删、且单向**：旧名进 `ATOMIC_OP_ALIASES`（运行时）或 `_EFFECT_ALIASES`（引擎），
   目标必须是真实实现；删除的名字进 `mod_spec_v2.REMOVED_ATOMIC_OPS` 并给显式报错（§5.4）。
6. **登记与验收**：op 进 `mod_spec_v2._CORE_LOGIC_OPS`；跑
   `python tools\mod_atom_report.py --check --strict`、`python tools\atom_parameter_table.py --check`、
   `python tools\op_long_tail_report.py`、`python .codex-tmp\smoke_all_cards.py`，
   并在 `.codex-tmp/roundNN/rdNN.md` 写报告（§8.3 的六步流程）。
