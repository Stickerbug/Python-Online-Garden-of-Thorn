# 新人权益与PvP奖励

实现版本：2026-09-01，P7。本地实现，未部署。规则由 `pvp_economy.py` 计算，数据库持有真实场次和结算记录，客户端只负责展示。

## 新人规则

- 有效PvP前10场（第1–10场）奖励最多乘2；第11场恢复普通倍率，不与新人头衔叠乘。
- 不满20场显示强制“新人”标记，完成第20场后自动移除。它不占可佩戴称号槽，也不能通过取消佩戴隐藏。
- 前三场天梯中的失败不减少赛季或总花阶，第四场起正常扣分。胜局也消耗这三场中的一场；保护不扩展到平局的评分差调整。投降按败局处理，适用相同新人保护，但60秒内投降仍扣信誉、双方无荆露。
- 旧账号按已有有效对局数和天梯历史判断；进入R1时沿用原有赛季/总花阶和计分场次，旧分归档只用于审计，不重复计数。旧赛季天梯场次也计入前三场资格。
- 已确认关联组按成员累计场次共享额度，仅最早注册的主账号可继续使用剩余额度。次账号不重新获得头衔、双倍或保护；疑似状态不会取消正常新人权益。误判解除后按真实账号场次重新判断，不伪造历史。

## 一场奖励怎么算

有效娱乐1v1/2v2与天梯1v1/2v2：胜利基础100，失败或平局60荆露。有效性沿用服务器正常终局和行动/时长检查，不把训练、协作故事或异常断线结局变成有效PvP。

连胜从第一次胜利额外+10开始，之后每胜+10，最高+100；失败或平局归零。60秒内投降的胜方不增加连胜，败方中断连胜。新规则上线时连胜从0开始，不追溯发奖。

```text
荆露 = floor(floor((基础奖励 + 连胜奖励) × 新人倍率 × 防刷倍率) × 信誉倍率)
```

新人倍率最多2；信誉40–59为0.5、低于40为0，否则为1。开局60秒内投降双方强制为0。关联组成员彼此参加同一局，相关账号不获得对局荆露或增长连胜；其他无关玩家不因此失去正常奖励。

延续现有衰减规则：

| 当天已结算场次 | 日常倍率 |
| --- | --- |
| 0–9 | 1 |
| 10–19 | 0.5 |
| 20以上 | 0.2 |

| 当天与同对手已结算次数 | 重复倍率 |
| --- | --- |
| 0–7 | 1 |
| 8–14 | 0.8 |
| 15–24 | 0.5 |
| 25以上 | 0.25 |

两者取较低值，不相乘。北京时间日界；2v2只数真正的对手，不把队友当成对手，也不能通过换队友重置计数。双方已确认关联账号按组累计；不同游客昵称统一计入游客对手档，不能靠改游客名重置。较高风险关联另受短局/重复对手限制。既有奖励流水继续计入当天额度。

## 幂等和历史记录

`pvp_reward_settlements` 按服务器生成的对局键及数据库比赛编号去重，并保存结算输入指纹与首次结果；相同重试返回原结果，变更胜负、成员或其他核心字段则拒绝。账号场次、连胜、荆露余额、货币流水及对手记录处于同一写事务，任何一步失败全部回滚。0奖励也记录结算，之后恢复信誉不能重领这局。

上线前已有货币流水的比赛不会因为缺少新账本而重新发钱。只读奖励试算使用同一计算器并回滚临时写入。天梯保护结果写进原始结算，历史重建沿用当时是否保护，不拿玩家现在的资历重新判断。

尚不声称能识别所有作弊：共用设备不等于同一人，换全新设备、网络的账号可能缺少足够证据。多信号阈值与申诉方式见 [信誉与关联账号](ACCOUNT_INTEGRITY.md)。
