# 自定义状态能力与官方状态原子化

> 目标：模组作者用 `registries.statuses` 里的**声明**就能定义状态行为，行为由
> 与卡牌相同的原子（`status_op` / `health_op` / `resource_op` / `log` / `if_else` …）
> 组合出来；原版 17 条状态逐步从引擎硬编码迁到同一套声明。
>
> 本文件描述**当前已实现的能力**与**剩余工作的分解**。权威数据仍是
> `official_statuses.py`、`docs/状态总表.md` 与代码本身；本文件只是路线图。

## 1. 现在能声明什么

状态资源（`registries.statuses[]`，以及官方 `official_statuses.py` 的同一形状）
现在支持这些字段：

| 字段 | 作用 | 状态 |
|---|---|---|
| `id` / `name_i18n` / `desc_i18n` / `color` / `icon` / `visible` | 展示层 | 已有 |
| `stacking` | `stack` 叠加、`duration` 取最大、`unique` 只留 1 层 | 已有 |
| `keep_when_zero` | 层数到 0 时保留一条 0 层记录 | 已有 |
| `show_stack` | 客户端是否显示层数 | 已有 |
| `events` | 在引擎阶段触发原子步骤 | 已有，阶段见下 |
| `max_stack` | 层数上限（0/缺省＝不限），超出即截断 | **本批接通** |
| `decay` | `{"timing": "turn_start"\|"turn_end", "mode": "one"\|"half"\|"clear", "log": false\|true\|"zero"}` | **本批接通** |
| `decay_timing` | 旧/简写：等价 `decay.mode = "one"`，可选 `decay_log` | **本批接通** |
| `stack_keys` | 这个状态的层数可能存放在多个 `custom_statuses` 键里；读取按声明求和，增删归并到第一个键 | **本批接通** |

`decay.log` 默认关闭；`"zero"` 只在减到 0 时写「效果消失」；`true` 每次衰减都写
`XX的YY减少N层（a→b）`。别名键（`frost` / `debt` 这类）在衰减时会归并到定义里的
规范 `id`，不会同一个状态留两份层数。

## 2. 状态事件阶段

`events` 的键是阶段名，值是步骤列表（或 `{"steps": [...]}`）。当前引擎会在这些
时点触发：

| 阶段 | 触发位置 | 上下文 |
|---|---|---|
| `on_apply` | 层数从 0 变正 | `amount` |
| `on_remove` | 层数从正变 0 | `amount` |
| `on_turn_start` | 自己回合最早的一批结算（正常回复之前） | `player_id` |
| `on_turn_start_before_status_damage` | 中毒/灼烧结算前 | `player_id` |
| `on_turn_start_after_recovery` | 正常回复 E 之后 | `player_id` |
| `on_poison_resolved` | 中毒伤害与减半结算之后 | `player_id` |
| `on_turn_end` | 自己回合结束 | `player_id` |
| `on_heal_pre` | 一次治疗落地前（`heal_block` 之后、护盾转化之前）；可读写共享变量 `heal_amount` | `heal_amount` |
| `on_damage_taken` | 自己受到伤害后 | `damage_amount`、`event_source_player`、`event_target_player`、`damage_source` |
| `on_damage_dealt` | 自己造成伤害后 | 同上 |

事件里的 `source_player` / `target_player` 保持「状态拥有者」的旧口径（Jungle
回合回复用 `{source}` 指代自己）。伤害相关的对象另放在 `vars` 的
`event_source_player` / `event_target_player` / `damage_amount`，以及上下文的
`source_id` / `target_id` / `damage_source`。

**先事件、后衰减**：`on_turn_start` / `on_turn_end` 跑完，才结算 `decay`。
因此「结算后减半」「结算后清除」可以只用声明表达。

## 3. 本批已经迁移的原版状态

| 状态 | 以前 | 现在 |
|---|---|---|
| `arctic:frost` | 引擎在本人回合结束写死 `// 2` | `decay: {timing: turn_end, mode: half}` + `max_stack: 60`；E 消耗 +1 仍是引擎数值钩子 |
| `jungle:fragile` | 引擎在回合开始写死清 0 | `decay: {timing: turn_start, mode: clear}`；护甲降低仍是引擎数值钩子 |
| `hel:blazing_fire` | `_hel_apply_blazing_fire_turn_start()` 在 1v1/2v2/URF 各调一次 | `events.on_turn_start_before_status_damage`：读层数 → `status_op(add, fire)` |
| `bio:debt` | `_bio_apply_debt_after_recovery()` | `events.on_turn_start_after_recovery`：免疫时不扣 E，但层数照常 -1 |
| `bio:extra_healing` | `_jurassic_redirect_healing()` 里写死加层数 | `events.on_heal_pre`：`add_var(heal_amount, status_stack)`；触发点与旧顺序一致 |
| `jungle:toxic_poison` | `_apply_toxic_poison_after_poison_settlement()` | `stack_keys` + `events.on_poison_resolved`：结算后按层数加中毒 |
| `jungle:turn_heal_turns` / `turn_magic_turns` | 更早批次已迁移 | `events.on_apply` + `on_turn_start` |

兼容性：`_hel_apply_blazing_fire_turn_start` 与 `_bio_apply_debt_after_recovery`
仍保留为普通方法，供旧调用方（例如训练/回放工具）使用；引擎回合流程不再调用它们。

## 4. 原版状态剩余分解

「层数直接换成另一种资源/伤害」这类已经可以纯声明；真正还需要新钩子的是
**改数值**和**拦截/替换结算**两类。建议按下面顺序继续：

### 4.1 只差一个触发点

| 状态 | 需要的阶段 | 说明 |
|---|---|---|
| `ocean:unable_counter` | `on_card_added_to_hand` | 抽到反制牌时自动弃掉并 -1；需要抽牌/入手钩子 |
| `ocean:blood_debt` | `on_damage_taken`（限物理） | 上下文已补攻击者/伤害量；还需把触发限制到物理伤害，并补上 2v2 目前缺失的路径 |

### 4.2 需要「数值修改钩子」

这些状态会改别的结算量，单靠现有事件不够，需要引擎提供**可被声明接管的数值管线**
（类似 `_run_v2_damage_modifiers` 的数据版本）。建议统一成下面四类钩子，
每类都在引擎现有结算位置上触发，声明只能改共享变量，不能自己再造一套结算：

| 钩子 | 触发位置 | 可读写变量 | 用途 |
|---|---|---|---|
| `on_cost` | 计算卡牌实际 E/M 消耗时 | `cost_e`、`cost_m` | 霜冻每 10 层 +1E |
| `modifiers`（被动块，不是 events） | 读护甲 / 受伤倍率时 | — | 易损 `armor -= stack`、树根 `armor += stack` |
| `on_damage_pre` | 伤害减甲前的修正管线（`_run_v2_damage_modifiers` 同一位置） | `damage_amount`、`damage_type`、`damage_tag` | 护盾抵扣、幸运暴击、其它减伤/增伤 |
| `on_heal_pre` | 治疗落地前（已实现） | `heal_amount` | 额外回复、护盾转化 |

`on_damage_pre` 的建议契约：

* 声明用 `set_var` / `add_var` 改 `damage_amount`，用 `status_op` 消费/清除自己的层数；
* 需要知道是否暴击时，用 `set_var` 写 `is_crit = true`，由引擎在钩子跑完后读取；
* 顺序按声明里的 `priority`（默认 0，小的先跑）再按状态 id 排，保证同一个对局
  可复现；护盾、幸运这类需要固定顺序的官方状态由声明里写死 priority；
* 钩子只改「本次伤害」的中间值，不允许在里面直接 `health_op lose`，避免绕过
  成就、死亡检查与其它修正。

`modifiers` 被动块的建议契约：

```json
{"modifiers": {"armor": {"op": "sub", "value": {"op": "status_stack"}}}}
```

它只在读数值时计算，不触发步骤，因此不会因为"读一次护甲"就反复跑事件。

按这个设计，剩余状态的迁移顺序是：

| 状态 | 要改的量 | 钩子形态建议 |
|---|---|---|
| `arctic:frost` | 卡牌 E 消耗 +⌊层数/10⌋ | `on_cost` + `add_var(cost_e, floor(stack/10))` |
| `jungle:fragile` | 护甲 -层数 | `modifiers.armor = sub(stack)` |
| `jungle:shield` | 受到伤害先扣层数 | `on_damage_pre` 高优先级：改 `damage_amount`、消费层数 |
| `hel:luck` | 暴击判定与倍率 | `on_damage_pre` 低优先级：消费层数、写 `is_crit` |
| `bio:shield_conversion` | 把回复改写成护盾 | `on_heal_pre`：`heal_amount = 0`、加护盾、清空层数 |
| `jungle:root_status` | 护甲 + 层数，受击扣装备层 | `modifiers.armor = add(stack)` + `on_damage_taken` 扣装备层 |
| `sewers:sealed` | 装备效果整体不生效 | 装备效果的 `disabled_if` / 标签，属于「标签」批次 |

### 4.3 标签与带层数的特殊效果

按用户要求本阶段不做：

* 状态上的 `tags` 查询/展示；
* 会改伤害、E 消耗、护甲、治疗量的「带层数特殊效果」；
* 装备/卡牌上的状态绑定与 `sealed` 一类开关。

## 5. 写卡示例

回合开始的持续伤害：

```json
{
  "id": "my_mod:bleeding",
  "stacking": "stack",
  "max_stack": 20,
  "decay": {"timing": "turn_end", "mode": "half"},
  "events": {
    "on_turn_start_after_recovery": [
      {"op": "set_var", "name": "bleeding", "value": {"op": "status_stack", "status": "my_mod:bleeding"}},
      {"op": "if_else",
       "condition": {"op": "compare", "a": {"op": "var", "name": "bleeding"}, "operator": ">", "b": 0},
       "then": [
         {"op": "health_op", "mode": "lose", "target": "self", "amount": {"op": "var", "name": "bleeding"}, "log": false},
         {"op": "log", "message": "{source}因流血受到{bleeding}点伤害"}
       ],
       "else": []}
    ]
  }
}
```

治疗量修正（`on_heal_pre` 的共享变量叫 `heal_amount`）：

```json
{
  "id": "my_mod:extra_healing",
  "stacking": "stack",
  "stack_keys": ["my_mod:extra_healing", "extra_healing"],
  "events": {
    "on_heal_pre": [
      {"op": "add_var", "name": "heal_amount",
       "value": {"op": "status_stack", "status": "my_mod:extra_healing"}}
    ]
  }
}
```
