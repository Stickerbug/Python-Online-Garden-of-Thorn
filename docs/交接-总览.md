## 5. 合成大花花榜单/奖励设计要点（已定稿）

- **每次分数变化就上传**（`{game_uid, from_index, drops, claimed_score, claimed_max_tier}`），服务端**立刻落库**；
- 服务端做**启发式校验**（物理游戏无法逐位重放、服务器没 node）：分数只增、单批增量 ≤ 投放数×`MAX_GAIN_PER_DROP`（=66×8，一次整条 7 级连锁合法就有 266 分）、投放间隔 ≥ 400ms、总分上限、
  **时间锚定**（投放时间戳的推进 ≤ 墙钟 1.5 倍 + 2 分钟，锚点=上次确认状态，见 `minigame_suika_service._check_time_anchor`）、累计投放 ≤ 10 万；
- 不通过 → 返回 `verified=false` + 原因，**只存进度不入榜，本地不删档**；且**不把异常投放/分数写进存档**（否则整局再也进不了榜）；
- 通过 → 写 `minigame_2048_records`（`game_key='suika'`）计入 14 天滚动榜；
- 周奖复用 2048 那套（`_split_pool` / `_credit_dew` 幂等），奖期键 `suika-YYYY-MM-DD`，结算 worker 已顺带调用 `minigame_suika_service.settle_due()`；
- 存档保留"种子 + 投放序列"，未来装了 node 可直接升级成完整重放。

### 第九批 玩家球渲染对齐 + 体积缩小（规则 v5，本地提交未部署）

用户：「合成大花花的玩家仍然与皮肤显示稍有不同，嘴粗了一些。且碰撞箱比看起来的
要小。同时把玩家的体积稍微缩小。」

- **嘴粗的根源**：canvas 把嘴的线宽按「直径×5.6%」画，但 CSS 里 5.6 是 viewBox(100×56)
  单位、SVG 等比缩放（meet，s=盒高 20%/56）——有效线宽只有直径的 ~1.7%。同时 CSS 的
  百分比子元素（眼睛/嘴）都落在 **border 内侧 content 圆**（直径 85%）里，canvas 却按
  整个物理圆画脸，整张脸都偏大。修法：drawPlayerBall 把脸画在 `radius - borderWidth`
  的内圆上，嘴按 viewBox 等比折算（线宽=5.6×s）。
- **碰撞箱偏小的根源**（两处视觉外溢，物理没变）：①玩家球边框 stroke 以路径为中心线，
  7.5% 边框有一半（3.75% 直径）画到物理圆外——路径缩到 `radius - borderWidth/2` 修掉；
  ②烘焙阴影 blur 0.22×半径 会在球沿外晕出暗圈，收到 0.11×半径。
- **体积**：玩家档半径再 ×0.9（`PLAYER_RADIUS_SCALE`，192×0.95×0.9=164.16），核心
  RULES_VERSION 4→5（旧档走「只保留分数」迁移，同第六批机制）；服务端榜单不分桶不变。
- **验证**：node 断言 v5/164.16；pytest 14 过（core 断言 4→5）；探针

### 第十批 修复：护盾抵扣的伤害带小数点（本地提交未部署）

用户 bug 报告：「护盾抵扣的伤害有时候带有小数点」。

- **复现**：即使伤害/层数全是整数（伤害 6、护盾 10 层），日志也打出
  「玩家2的护盾抵扣**6.0**点伤害」。根因在 mod_runtime_v2 的 op 算术层：
  `_to_number` 把操作数一律转 float，`min(6.0, 10.0)` 返回 6.0，
  `log` op 的 `_format_message` 又是裸 `str(var)` → ".0" 泄进所有走算术 op 的日志。
- **修复**（两层，与 modify_event_value 既有归一同口径）：
  ①算术层 add/sub/mul/min/max 结果经 `_as_clean_number`（整数浮点→int；
  div 不动——真除保留浮点是 Round 49 契约）；②`_format_message` 占位符渲染走
  `_format_log_value`（整数浮点不带 .0，非整数如 3.5 原样）——兜住 div 等仍传浮点的值。
- **测试**：test_declarative_status_fields.py 新增
  `test_shield_absorb_log_has_no_trailing_decimal`（引擎级断言日志无小数 + 渲染函数单测）；
  相关 10 组 121 passed + 44 subtests。
- **注意**：这是框架级改动——所有卡牌/状态里走算术 op 的日志都会跟着变干净，
  数值本身不变（6.0→6 只是类型归一，比较/入层早有 int 门槛）。
