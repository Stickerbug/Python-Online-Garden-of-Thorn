## 5. 合成大花花榜单/奖励设计要点（已定稿）

- **每次分数变化就上传**（`{game_uid, from_index, drops, claimed_score, claimed_max_tier}`），服务端**立刻落库**；
- 服务端做**启发式校验**（物理游戏无法逐位重放、服务器没 node）：分数只增、单批增量 ≤ 投放数×`MAX_GAIN_PER_DROP`（=66×8，一次整条 7 级连锁合法就有 266 分）、投放间隔 ≥ 400ms、总分上限、
  **时间锚定**（投放时间戳的推进 ≤ 墙钟 1.5 倍 + 2 分钟，锚点=上次确认状态，见 `minigame_suika_service._check_time_anchor`）、累计投放 ≤ 10 万；
- 不通过 → 返回 `verified=false` + 原因，**只存进度不入榜，本地不删档**；且**不把异常投放/分数写进存档**（否则整局再也进不了榜）；
- 通过 → 写 `minigame_2048_records`（`game_key='suika'`）计入 14 天滚动榜；
- 周奖复用 2048 那套（`_split_pool` / `_credit_dew` 幂等），奖期键 `suika-YYYY-MM-DD`，结算 worker 已顺带调用 `minigame_suika_service.settle_due()`；
- 存档保留"种子 + 投放序列"，未来装了 node 可直接升级成完整重放。

### 第九批 玩家球渲染对齐 + 体积缩小（规则 v5，本地提交未部署）

## 6. 已知坑（踩过的）

- **canvas drawImage**：给 SVG 贴图用 9 参数写法时若 `naturalWidth` 为 0 会**静默不画**；改 3 参数写法。
- 小游戏页收大厅聊天靠 `lobby_chat_history` **整段推送**（不是逐条 `chat`），未读按消息 id 增量计；两个事件都要接。
- 棋盘手势要 `touch-action: none`；模块没加载要有 `#sk-boot-error` 兜底提示。
- 首次进页面很多内容空白 → 多数是模块/骨架没跑完，检查 SW 缓存清单与脚本顺序。
- Playwright：`eval` 单行、避免 `&`、导航后另起 eval；`resize` 后等 1s 再截图。
- 服务器没 node；`sqlite3` 迁移一律用"加列 + 默认值"的增量写法。
