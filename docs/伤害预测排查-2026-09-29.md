# 伤害预测排查（2026-09-29）

## 现状架构

- **服务端反制窗口预测**：`_simulate_pending_response_damage`（game_engine.py）
  用 `copy.deepcopy(self)` 在副本上真实结算再读日志——**与引擎同一套代码，
  天然不会漂移**。
- **客户端出牌/卡面预测**：game.js 约 13800–15200 行的手写镜像管线
  （`simulatePredictionAttackRawHits` / `appendTargetDamagePrediction` /
  `predictionOutgoingDamage` / 各种 `addKnownSelfPrediction` 特判表）。
  **每次改卡/改引擎都要手动同步一遍**——本次排查确认已漂移。

## 已确认的漂移（实测代码比对）

| # | 项目 | 客户端现状 | 引擎现状 |
| --- | --- | --- | --- |
| 1 | **血盾下限** | `createPredictionDamageRuntime` 完全没有血盾字段——预测伤害**从不**被血盾拦 | 2v2 逐玩家血盾下限（本轮又改为各自回合衰减+floor(2/3)→floor(1/3)→0）。2v2 里血盾生效期所有伤害预测一律偏高 |
| 2 | **虚弱减伤** | `min(0.6, 0.2×层数)`——多层成倍减 | 9.22 起固定 -20%（仅 1 层时碰巧一致，2/3 层时客户端多减） |
| 3 | **威力分摊** | 术语说明与多处公式仍是"每段+ceil(威力/段数)" | 9.27 改第一段全额；9.29 又修裂变迭代不重复加。沙子类卡的预测段值与实际不符 |
| 4 | **裂变段生成** | 客户端按 `hits×2^(裂变-1)` 一次算段 | 引擎按裂变迭代逐次结算（每段独立过护甲/邪眼/闪避）——减免类目标上预测偏差放大 |
| 5 | **特判表腐化** | `addKnownSelfPrediction` 按卡 id 硬编码（Fang/Fries/…） | 卡数据改版后特判不跟（锯片流血删除后自伤/状态特判类同风险） |

> 未逐卡全查（工作量=逐卡对拍）；以上 5 项为结构性确定项，其余卡面数字
> 建议按第 2 节方案一次性消除。

## 通用方案建议（一次做完，以后不用再改）

**把出牌预测也搬到服务端模拟**，与反制窗口同一套机制：

1. 新增轻量接口（socket 或 HTTP）：客户端在**悬停/选中手牌**时带上
   `instance_id + 目标座位`，服务端 `sim = copy.deepcopy(engine)`，
   在副本上把这张牌真实打出去，返回结构化结果（每段伤害、施加状态、
   自伤/回复、资源变化）。
2. 客户端删掉手写镜像管线，只留**渲染**（现有的预测展示 UI 不动）。
3. 成本控制：引擎 deepcopy 较重——按"每状态版本+卡+目标"做 LRU 缓存；
   只在玩家悬停时按需计算（不是每张常驻）。天梯对局 4~7 张手牌 ×
   悬停频率，单次几十 ms 级，可接受；不行再加状态版本号短路。
4. 迁移：客户端管线先保留为接口失败时的兜底，逐包切换后删除。

替代方案（不推荐）：继续手动同步客户端公式——每次改卡都要重做，正是
本次要避免的。

## 建议实施顺序

1. 服务端模拟接口 + 手牌悬停预测接入（P0：伤害数字）。
2. 状态/资源预测（P1：施加状态层数、自伤回复）。
3. 删除客户端镜像管线与特判表（P2，观察一周后）。
