# 默认值差异判定清单（Round 82 / 批次 CD）

> 来源：`docs/原子参数表.md` 附录 C（由 `tools/atom_parameter_table.py` 生成）里的
> "同名参数默认值不一致"15 条 + `.codex-tmp/round86/default_conflict_audit.py` 对官方
> 20 个包 352 张卡的**显式写出率**统计。
>
> 结论先说：**默认值不一致不等于 bug**。多数是"同一族里不同实现体各有各的默认"，
> 而且官方卡数据基本都显式写了参数、压根走不到默认值。这份清单把"改了会变行为"的
> 那几项挑出来，等你点头再动。

## 一、判定依据

* 官方数据里的**显式写出率**：写了 → 默认值不生效，改它零风险；没写 → 默认值就是行为。
* 两条执行路径：
  * **运行时路径** = `mod_runtime_v2.run_v2_step`（卡数据绝大多数步骤走这条）；
  * **引擎路径** = `game_engine._atomic_*`（嵌套 `body`、定时器体、旧 `effects` 写法走这条）。
* 验收口径（真要改时）：`python .codex-tmp/round46/rd46_ab.py` 全卡 A/B **0/704** +
  `python .codex-tmp/smoke_all_cards.py` 0 失败 + 定向 pytest。

## 四、抽取器口径问题（不是真差异，已记档）

| op / 参数 | 现象 | 说明 |
|---|---|---|
| `random` / `a`·`b` | 默认值显示为 `1` / `[…]` | 这两个键是"候选池"和"抽几张"，形态不同不是冲突；该 op 官方 0 步使用 |
| `player_var_change` / `value` | `0` / `0`·`1` | 同一 op 的 `mul`/`div` 模式默认 1、其余默认 0——是"按模式"而不是"按路径" |
