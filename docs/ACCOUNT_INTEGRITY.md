# 信誉、队友举报与自动关联账号

实现版本：2026-09-01，P6。本地已实现，未发布到服务器。

本文件说明当前规则与具体识别方法。服务端 `account_integrity.py` 是规则实现，`db.py` 保存账本，`app.py` 负责可信身份与触发点。客户端不能提交信誉值、风险分或关联结论。

## 信誉与奖励

所有账号初始85，范围0–100，不追溯历史扣分。首次初始化、处罚、恢复、关联及解除均有流水；撤销使用反向补偿，不改写旧处罚。

| 信誉 | 公开标记 | 服务端限制 |
| --- | --- | --- |
| 80–100 | 无 | 无 |
| 60–79 | 黄色低信誉 | 无额外限制 |
| 40–59 | 橙色低信誉 | 暂停成就进度、解锁和奖励；赚取的免费荆露减半，向下取整 |
| 0–39 | 红色低信誉 | 以上限制，并禁止新建/加入天梯、不发赚取的荆露 |

已开始的天梯照常完成花阶结算，不因中途扣信誉变成无效局。购买、退款及管理员补偿不是赚取奖励，不乘信誉倍率。

北京时间跨日检查前一天：没有扣分且参加过天梯，恢复5点。信誉低于40只免除参赛要求，不免除“前一天无扣分”。即使信誉已为0，当日发生处罚也算扣分日。离线账号可以补处理跨日；账号或关联组每日仅一次，封顶100。

- 60秒内投降：天梯扣2，娱乐扣1；2v2只扣实际发起投降的玩家。双方均无对局荆露。
- 连续两次自己的回合被计时器自动结束：天梯扣5，娱乐扣1。正常手动结束回合会重置连续计数；仅出一张牌不算正常结束。
- 队友举报经对手确认：天梯扣5，娱乐扣1。

## 2v2举报流程

仅支持四个注册账号组成的已结束2v2。队友在结算后10分钟内填写理由；同一举报人对同局同队友只生成一条举报。任何一名对手可在结算后24小时内确认。举报者、被举报者和无关玩家不能代替对手确认。

待确认时举报者可撤回；超时自动过期；任何重试都不能重复扣分。Staff/Admin 可说明理由撤销已成立举报，按原流水实际扣除值返还，保留原举报和审计。提交及处理始终按数据库中的队伍归属验证，而非客户端展示。

## 自动识别怎样工作

识别是风险判断，不能证明两个人现实身份相同，也无法保证发现换设备、换网络的全部小号。

浏览器接收服务端签发的随机设备 Cookie（HttpOnly、SameSite=Lax，HTTPS下Secure）。设备和网络标识分别经域隔离HMAC后入表，不采集Canvas等浏览器指纹，不保存原始IP到关联表。IPv4按地址、IPv6按/64网段归类。专用 `GTN_ACCOUNT_LINK_HMAC_KEY` 未配置时从应用会话密钥派生；部署应保持密钥稳定，不向客户端暴露。客户端任意伪造或改写Cookie签名不会成为有效设备令牌。

最近30天信号参与评分；同账号、设备、网络、来源和北京时间日期重复事件只记一次。30天是评分窗口，不是当前数据库自动删除承诺；现有关联及审计保留供申诉复核。

| 信号 | 分数 | 可复查的具体条件 |
| --- | --- | --- |
| 同设备 | 50 | 两个账号使用过同一有效服务端设备令牌 |
| 稳定设备 | 25 | 同设备在至少3个共同日期出现 |
| 多日同网 | 15 | 至少3个共同日期使用相同网络标识 |
| 短期注册 | 10 | 两个账号在24小时内于同网络注册 |
| 持续异常短局 | 20 | 两账号共同参与至少4场60秒内投降，分布在至少3个日期 |
| 模糊花阶相似 | 10 | 一个账号仅有1–10场天梯、另一个超过10场，当前总花阶落在同一50分档 |

任意网络在一天出现至少8个账号，即按共享网络处理，网络类总分最多5。共享网络即使共用浏览器、花阶相近，也必须额外命中持续异常行为才能自动确认。

- 低于40：无可见风险状态。
- 40–69：疑似，不共享信誉，不取消新人权益。
- 70–89，或总分足够但独立证据不足：较高风险，仅限制可疑短局/重复对手奖励。
- 至少90，且至少两类独立信号、其中包含设备或持续行为，并通过共享网络保护：自动确认关联。

设备50和跨日设备25属于同一类，不能冒充两类证据。IP永远不能单独确认。普通长局和仅拥有相同对手不算异常行为。

注册、登录、会话恢复、比赛结算触发重算；后台每10分钟补做最近活跃账号的重算及信誉恢复、举报过期。相同输入使用固定指纹去重。确认组不会因30天信号淡出而自动拆散；解除过的账号对不会因下次登录被自动合回。

## 分组、隐私和申诉

确认时以组内最低当前信誉建立共享信誉；以后任何成员被扣分或符合恢复条件，作用于同一组账本。不会因换小号恢复85，也不会按成员数多领每日恢复。组级处罚查询会保留合组前的扣分日，避免当天先被扣再合组绕过恢复条件。

服务器从关联成员真实总花阶计算最大值；公开只显示 `floor(max/50)*50` 到 `+49` 的区间，不能由管理员手工录入或客户端上报。自己的完整信誉与流水只有自己及有权审核者可见；大厅、对局、聊天只显示等级标记和模糊区间，不公开关联成员、网络、设备或精确关联花阶。

账号可以在“账号信息 → 信誉与队友举报”申诉。申诉期间保留既有组规则，但阻止自动扩组。Staff/Admin 可查看风险理由、处理申诉，或凭明确理由合并/解除；解除必须显式给出0–100的起始信誉。直接解除也会收尾对应未决申诉。界面和数据库两层验证角色，所有处理保留操作者、理由及前后状态。

私有接口禁缓存。面板关闭或切换账号会清除表单与已载入数据；旧请求不能把上一账号的审核资料重新渲染到新账号。

## 验证入口

`tests/test_account_integrity.py` 覆盖阈值、北京时间日界、幂等并发、举报角色与窗口、撤销补偿、共享网络误判、签名Cookie、自动分组及申诉解除。`tests/test_account_session_takeover.py` 覆盖同账号连接接管；信誉读取失败必须先拒绝新登录，不能踢掉旧连接。
