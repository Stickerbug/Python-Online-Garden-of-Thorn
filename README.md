# Garden of Thorn / 荆棘花园

Garden of Thorn / 荆棘花园是一款浏览器端回合制卡牌游戏，包含多人对战、单人训练场和带账号进度的故事模式。

玩家需要管理生命（H）、能量（E）与魔力（M），使用攻击（Thorn）、技能（Bloom）、装备（Root）和反制（Guard）四类卡牌，通过伤害、回复、状态、装备与回合外响应建立优势。多人标准对局中，玩家通常先通过“三选一”构筑 15 张牌，再进入正式战斗。

本项目是基于 Flask + Socket.IO 的 Python 联机版，支持浏览器图形界面、局域网及互联网部署。原生 Godot 版已停止开发，详见 [Garden of Thorn 的 Godot 版仓库](https://github.com/Stickerbug/Garden-of-Thorn)。

## 游戏模式

### 多人游戏

- **1v1**：两名玩家完成配装与选牌后轮流行动，先使对手阵亡的一方获胜。
- **2v2**：四名玩家分为两队。卡牌可按规则选择敌人、自己或队友，阵亡玩家仍可能被复活，一队全部阵亡时对局结束。
- **无限火力**：不进行配装和选牌的快速 1v1。双方从当前模组的随机牌池获得手牌，可替换手牌并售卖装备；部分会破坏循环的卡牌不会进入该模式。
- **随机卡组**：不进行配装和选牌。系统从双方共同选择的模组中按权重生成相同的 15 张牌，其中包含 6 张攻击、4 张技能、3 张装备和 2 张反制。

多人游戏还包括大厅邀请、聊天与社交、断线重连、观战、回放、举报和对局反馈。符合条件的注册账号对局会参与花阶分（Garden Rating）与排行榜统计。

### 单人训练场

单人训练场用于测试正式对局规则、卡牌组合和极端数值，不影响多人排名。双方牌组均可由玩家自由配置，每方允许 0 至 50 张牌，并可设置开局事件和配装。训练中支持撤销、重做、调整抽牌顺序等调试操作。

### 故事模式（测试中）

故事模式是独立于多人对战的单人爬塔玩法，仅登录账号可以进入，进度保存在服务器中。其卡牌平衡和部分规则独立于多人模式。

- 可选择标准旅程或 Boss Rush，以及简单（Easy）、普通（Normal）、困难（Hard）和疯狂（Lunatic）难度。
- 在地图中经历战斗、精英、首领、事件、休息区、商店和宝箱等节点。
- 在四类基础卡牌之外，故事牌组还会出现诅咒（Curse）和状态牌（Infect）。
- 构筑并升级牌组，获得天赋与赐福，使用故事模式金币（G）购买、升级或移除内容。
- 支持手动存档、读取、删除存档、重新开始本层，以及卡牌、生物、天赋和术语图鉴。
- 战斗使用经典 UI，并与多人大厅共享聊天。

> 故事模式仍处于测试阶段，关卡、数值、存档结构和已有进度可能随开发调整或重置。

## 主要功能

- 双资源、状态、装备、反制、伤害预测与多目标结算等完整对战系统。
- 经典 UI 与简约 UI，支持鼠标、触摸和可自定义键盘快捷键。
- `.gtnmod` 模组卡池、游戏内图鉴、卡牌术语和多语言描述。
- 注册账号、好友与私信、称号、成就、荆露、每日签到和每日任务。
- 赛季与总计花阶分排行榜、对局统计、观战和可下载回放。
- 中文、英文、法文和日文界面，明暗主题、音频设置和移动端适配。
- 独立 Web 管理终端，提供命令树、参数补全、在线状态与内容管理等功能。

## 快速开始

### 环境要求

- Python 3.10 或更高版本
- 现代浏览器

### 安装与启动

1. 克隆仓库并进入目录：

```bash
git clone https://github.com/Stickerbug/Python-Online-Garden-of-Thorn.git
cd Python-Online-Garden-of-Thorn
```

2. 建议创建虚拟环境，然后安装依赖：

```bash
python -m venv .venv
```

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Linux / macOS：

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
```

3. 启动服务器：

```bash
python app.py
```

默认监听 `127.0.0.1:5000`，在本机打开 `http://127.0.0.1:5000` 即可进入游戏。端口可通过 `GTN_PORT` 或 `PORT` 修改。

如需在局域网中访问，可将监听地址改为 `0.0.0.0`：

```powershell
$env:GTN_BIND_HOST="0.0.0.0"
python app.py
```

公网部署建议继续让应用监听本机地址，并通过 Nginx 等反向代理提供 HTTPS 与 WebSocket 连接。

> 本机测试多人对局时，请使用不同浏览器、不同浏览器配置文件或隐私窗口，并使用不同账号或游客身份。普通标签页会共享登录会话，不适合模拟两个独立玩家。故事模式必须使用已登录账号。

## 基本流程

### 标准多人对局

1. 登录账号或以游客身份进入多人大厅。
2. 选择模式和模组，邀请玩家；双方模组选择兼容后才能开始。
3. 标准模式依次完成配装选择、选牌、配装处理和开局抽牌。
4. 行动阶段中选择手牌和合法目标；满足条件时，其他玩家可在反制窗口响应。
5. 结束回合后结算相应效果并将行动权交给下一名可行动玩家。
6. 对局结束后可查看结算、申请再来一局、观看回放或返回大厅。

### 故事模式

1. 登录账号并从主页进入故事模式。
2. 选择旅程类型、区域和难度，完成初始牌组与赐福选择。
3. 沿地图路线进入节点，通过战斗和事件构筑牌组、获得天赋并管理金币与生命。
4. 在路线界面管理存档；已发现的卡牌、生物、天赋和术语会记录到故事图鉴。

## 操作提示

- 卡牌会显示 E 与 M 消耗；消耗不足、目标不合法或当前流程不允许时无法打出。
- 反制牌只能在对应的响应窗口中使用，装备的可触发效果会在满足条件时高亮。
- 左右键、触摸和快捷键的具体行为会随经典 UI、简约 UI 及当前选择流程调整；按 `/` 可查看当前场景的快捷键总览。
- 卡牌、标签、状态和装备可打开术语说明；图鉴可用于查看当前卡池和抽取概率。
- 观战和回放只展示当前规则允许观察到的信息。

## 蓝绿更新与排空

服务已经支持蓝绿部署和排空模式：新实例接收新玩家与新对局，旧实例保留已有对局及其断线重连，待房间清空后再停止。完整操作流程见 [`scripts/BLUE_GREEN_DEPLOY.md`](scripts/BLUE_GREEN_DEPLOY.md)。

常用准备命令：

```bash
scripts/blue_green_prepare.sh /opt/gtn-release /opt/gtn-next 5002 release
```

实例可通过以下环境变量标识：

```bash
GTN_INSTANCE=release
GTN_INSTANCE_ID=release-5002-version
GTN_VERSION=version
GTN_GIT_SHA=current-commit
GTN_STATIC_VERSION=current-commit
GTN_BIND_HOST=127.0.0.1
GTN_PORT=5002
```

管理终端中的排空命令：

```text
drain status
drain on
drain off
```

## 项目结构

| 路径 | 用途 |
| --- | --- |
| `app.py` | Flask + Socket.IO 入口，负责账号、会话、大厅、房间、观战、API 与服务管理 |
| `game_engine.py` | 1v1 和单人训练场的主要对战规则 |
| `game_engine_2v2.py` | 2v2 队伍规则与多人状态输出 |
| `game_engine_urf.py` | 无限火力规则 |
| `cards.py` | 卡牌定义、实例和基础牌池逻辑 |
| `mod_loader.py`、`mods/` | `.gtnmod` 模组加载与内容包 |
| `story_mode.py` | 故事存档、地图生成和旅程状态 |
| `story_engine.py` | 故事战斗、节点与操作结算 |
| `story_content.py` | 故事卡牌、生物、天赋、事件和难度数据 |
| `story_discovery.py` | 故事图鉴与发现记录 |
| `db.py` | 账号、社交、统计、成就、回放索引和故事进度持久化 |
| `templates/index.html`、`static/js/game.js` | 主页、多人游戏和训练场前端 |
| `templates/story.html`、`static/js/story.js` | 故事模式前端 |
| `static/css/` | 游戏、故事模式和管理界面样式 |
| `docs/` | API 权限清单、卡牌描述规范等开发文档 |
| `scripts/` | 蓝绿部署、健康检查、备份和数据维护脚本 |
| `tests/` | 对战规则、故事模式、接口与回归测试 |
